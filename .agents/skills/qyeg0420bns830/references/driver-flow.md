# 驱动与验证

以下为控制器级流程骨架。奇耘本型号初始化值、LUT、VCOM、复位脉宽及更新控制字取得并核对后才能形成可烧录的面板配置。

## 命令索引

SSD1683 Rev 1.0 第 26–37 页命令表：

| 命令 | 用途 |
| --- | --- |
| 0x12 | 软件复位，随后等待 BUSY 释放 |
| 0x11 | 数据写入方向与地址递增规则 |
| 0x44 / 0x45 | X 字节窗口 / Y 像素窗口 |
| 0x4E / 0x4F | X / Y RAM 指针 |
| 0x24 / 0x26 | 黑白 RAM / 第二 RAM 通道 |
| 0x18 | 温度传感器选择 |
| 0x32 | LUT 写入，参数采用匹配面板的波形 |
| 0x3C | 边框波形 |
| 0x21 / 0x22 | RAM 显示选项 / 更新序列控制 |
| 0x20 | 激活更新序列 |
| 0x10 | 深睡控制 |

第二 RAM 通道在芯片手册中命名为 RED RAM，其在黑白波形下的用途应按本屏程序核对。

## 初始化与全刷

1. 电源稳定后执行面板规定的硬件复位，等待 BUSY 空闲。
2. 软件复位，等待完成；设置扫描方向、窗口、指针、温度来源、边框和波形。
3. 设置全帧窗口，按本屏方案写入所需 RAM 通道。
4. 配置更新序列并激活，等待 BUSY 释放。
5. 成功后记录已显示帧和波形模式，再进入空闲或休眠流程。

400x300 的 X 字节地址范围为 0–49，Y 像素范围为 0–299；写入起点和顺序随扫描模式确定。刷新标称 4 s 作为测量参考，截止时间须包含温度和模式裕量。

## 局刷

先建立完整画面基准，再设置对齐后的更新窗口和对应新旧数据，按奇耘局刷波形更新。记录局刷累计次数、面积、温度和最近全刷时间。残影、模式切换或状态丢失触发全刷恢复；具体次数与间隔由实屏验收确定。

Waveshare 示例中的 0xF7、0xC7、0xFF 更新控制值及其 LUT 属于该模块实现，移植前需要本型号证据。该示例的 `display_Partial` 仍设置完整 RAM 窗口，不能据函数名称推断其支持任意小窗口传输。

## 休眠与恢复

SSD1683 第 26、42、44 页：`0x10, 0x01` 进入保留 RAM 的深睡模式 1；`0x10, 0x03` 进入不保留 RAM 的模式 2。两者都需要硬件复位退出。RAM 保留不等于唤醒后旧帧状态已经验证，应重新建立相应显示基准。

刷新完成后按面板方案关闭高压，再进入休眠或切断电源。异步等待刷新期间释放共享 SPI 总线，按设备维度串行化显示操作；BUSY 等待不应长期占用其他外设需要的总线锁。

超时记录操作阶段、最后命令、BUSY 电平、耗时和供电状态；采用有限次数复位/重新初始化恢复。刷新中断或掉电后把面板帧状态标记为未知，重新写入全帧。

## 验证

主机测试覆盖位序、边界、旋转、局刷字节对齐、SPI 错误传播、BUSY 截止时间、状态切换和成功后的旧帧提交。测试应验证行为与数据一致性。

实屏验证全白、全黑、棋盘格、四角标记与文本；测量刷新时长、局刷残影、睡眠电流和刷新瞬态压降。逻辑分析仪检查 SPI 时序及 RESET/BUSY 关系。记录屏幕标签、转接板版本、固件提交、波形来源、环境温度和供电方式。
